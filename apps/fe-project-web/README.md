# fe-project-web

React 19 + Vite 7 + Tailwind CSS 3 + React Hook Form frontend for the project service.

## Setup

From the repo root:

```bash
npm install
```

## Scripts

Run from `apps/fe-project-web` (or via Turbo from the root):

| Script              | What it does                                |
| ------------------- | ------------------------------------------- |
| `npm run dev`       | Vite dev server on http://localhost:5173    |
| `npm run build`     | Type-checks, then builds to `dist/`         |
| `npm run preview`   | Serves the production build locally         |
| `npm run lint`      | ESLint (`@fs-platform/eslint-config/react`) |
| `npm run typecheck` | `tsc --noEmit`                              |

## Layout

```
index.html               Vite entry document
src/main.tsx             React root: kit CSS, app SCSS, OnetalentUIKitProvider
src/app.tsx              Root component
src/styles/index.scss    Kit token layers + Tailwind directives
src/styles/_fonts.scss   ADNOC Sans @font-face rules
src/assets/fonts/        ADNOC Sans woff2/eot files
tailwind.config.ts       Tailwind 3 config, theme sourced from fe-ui-kit
postcss.config.js        Tailwind + autoprefixer PostCSS pipeline
```

Styling is Tailwind utility classes only — no CSS modules or styled-components. TypeScript config comes
from `@fs-platform/tsconfig/react.json`.

## UI kit

Components and design tokens come from [apps/fe-ui-kit](../fe-ui-kit), a prebuilt artifact linked as the
npm workspace `fe-ui-kit`:

```tsx
import { Button, Card, Input } from 'fe-ui-kit';
```

Three pieces have to stay in sync for the kit to render correctly:

1. **Externals** — the kit bundle does not ship `react`, `react-dom`, `react-hook-form`, `@epam/uui` or
   `@epam/uui-core`; they are direct dependencies here. `@epam/uui` peers React 18, so the root
   `package.json` `overrides` block pins React 19 into it.
2. **Tailwind** — `tailwind.config.ts` imports `theme` from `fe-ui-kit/tailwind/config` and scans
   `../fe-ui-kit/index.es.js`, because the kit's `styles.css` carries only vendor CSS; every utility class
   its components use is generated by _this_ app's Tailwind build. `tailwind-scrollbar` and
   `@tailwindcss/container-queries` are required by the kit's styles. The config is excluded from
   `tsconfig.json` since the kit's prebuilt TS sources predate `verbatimModuleSyntax`.
3. **Styles** — `src/styles/index.scss` pulls the kit's `@layer base` token sheets
   (`fe-ui-kit/scss/{light,dark,styles}`), which resolve Tailwind `theme()` calls, so they must be
   compiled by this app. Dark mode is `data-theme="dark"` on any ancestor (usually `<html>`).

Wrap the tree in `OnetalentUIKitProvider` (done in [src/main.tsx](src/main.tsx)) so modals, toasts and
tooltips get their portal container.

`apps/fe-ui-kit` is git-ignored, so a fresh clone has to drop the built kit in again. Its `package.json`
needs these entries for this app to resolve it:

```jsonc
"exports": {
  ".": { "types": "./lib/index.d.ts", "import": "./index.es.js", "require": "./index.cjs.js" },
  "./styles.css": "./style.css",
  "./scss/light": "./lib/styles/scss/_light.scss",
  "./scss/dark": "./lib/styles/scss/_dark.scss",
  "./scss/styles": "./lib/styles/scss/styles.scss",
  "./tailwind/config": "./tailwind/config/index.ts"
}
```

Its `dependencies` can stay empty — everything except the externals above is already inlined in the
bundle — and its React peers must allow `^19.0.0`.
